# M9 external-agent acceptance

M9 is accepted against immutable implementation commit
`b910e0179765e05f8c5dc3e0aa2f031660384317`, GitHub Actions run
[`31651785611`](https://github.com/Mischa-dev/agent-workspace/actions/runs/31651785611),
and the matching Red Hat release. Both protected `rust` and `web` jobs passed.

## Actor and authorization contract

- An owner connected Hermes as its own `external_agent` Actor with a Project
  membership and explicit `read`, `write`, `events`, `approval_respond`, and
  `worker_request` scopes.
- Reads, Messages, Work Item mutations, approval access, and sponsored Worker
  requests used the same centralized policy and Project scope as human actions.
- A live Hermes-authored Message and Work Item create/update retained the
  external Actor attribution. Clients never supplied human authorship.
- Permission changes, membership state, credential state, and connection state
  were revalidated at the mutation and polling boundaries.

## Pinned live connector

The connector used release tag `v2026.8.3`, commit
`3c27eb6234bf91b8ceee9e9071591b31e9b148cb`, Python 3.12.12, and the
checksummed 70-package isolated environment. Hermes negotiated Streamable HTTP
MCP `2025-11-25`, discovered 23 server tools, and enabled an exact 22-tool
least-privilege allowlist. Resources, prompts, sampling, elicitation, parallel
tool calls, GitHub publication, and integration management remained disabled.

The inference login used the owner's personal ChatGPT account in a separate
Hermes profile. Agent Workspace neither hosted Hermes nor controlled its model,
memory, schedules, skills, sessions, gateway, or autonomy loop. The existing
Hermes `0.18.2` command and gateway continued independently.

## Polling, credentials, and revocation

Two polls from the same opaque cursor returned the identical ordered event
sequences 11 through 18 and the same next cursor. Rotation invalidated both the
previous bearer and its credential-bound cursor. Live HTTP outcomes were:

- previous bearer after rotation: 401
- rotated bearer: 200
- bearer while connection disabled: 401
- newly issued bearer after re-enable: 200
- final bearer after connection removal: 401

The browser displayed each bearer once. It was transferred only to an
owner-only isolated secret file, the Mac clipboard was immediately cleared,
and all revoked copies were scrubbed after the proof.

## Human-sponsored hosted execution and restart

Hermes requested bounded repository work against an existing Thread and trusted
repository. The request created only a durable human-required approval. The
Agent Run, logical workspace, branch, physical worktree, and provider session
were created only after the signed-in human sponsor approved it through the
browser using the personal Codex profile.

The live timeline contains external Message attribution, command and file
events, one consolidated Worker Message, and terminal execution state. For the
restart proof, PostgreSQL showed the controlled run as `working` immediately
before systemd restart. Startup reconciliation reported one recovered run and
the browser displayed a Recovery entry. The run became `interrupted` with an
actionable reason; its branch, exact base commit, clean worktree, and provider
Thread were preserved, with no manual database or filesystem repair.

## Security and residual boundaries

Fixtures contain only bounded outcome labels and placeholders. They exclude
bearers, model credentials, prompts, Message bodies, reasoning, repository
content, browser state, raw database rows, and absolute runtime paths. System
Node, global Codex, existing Tailscale routing, unrelated Podman projects, and
retained dirty worktrees were not reconfigured or removed.

The product remains a private loopback/SSH-forwarded single-host deployment.
M9 does not add a public endpoint, agent OAuth, hosted external runtimes,
multi-runtime abstraction, billing, public multi-tenant isolation, or a promise
of exactly-once event delivery.
