# M3 hosted execution acceptance

**Status:** Foundation verified; M3 not yet accepted

**Implementation branch:** `codex/m3-foundation`

**Runtime acceptance target:** Red Hat Enterprise Linux 10.1 ARM64

## Current boundary

This record covers the first production-shaped M3 slice: durable Execution
Worker, Provider Connection, Execution Profile, Repository, Repository
Workspace, Provider Session, and Agent Run ownership/admission foundations. It
does not claim that the remaining M3 process supervisor, account ceremonies,
repository preparation, scheduler, normalized provider-event stream, recovery,
frontend controls, or browser-driven hosted run have been accepted.

The foundation adds authenticated, Project-scoped status-only APIs for
Execution Workers and Execution Profiles. Browser DTOs expose fixed provider
capabilities, bounded status, Actor identity, optimistic versions, health time,
and redacted failure categories. They exclude `CODEX_HOME`, repository and
worktree paths, host identity, credentials, arbitrary provider JSON, and raw
errors.

## Migration and host-path evidence

- `0009_m3_execution_foundation.sql` adopts the accepted M0 execution rows,
  adds same-Project composite keys and foreign keys, optimistic versions,
  provider capability and binary pins, profile account/concurrency state,
  repository preparation/archive state, Provider Session repository scope,
  Agent Run Project/turn identity, one active provider turn per profile, and
  immutable identity/admission triggers.
- The retained Red Hat development database applied `0009` during the
  persistent upgrade smoke before final cross-review. Its SHA-384 is
  `626deed7d479bda932eb1598e93d6e65855d5619c89b5f6736c69772639f2d530e8e4345c4481a9a9fa8c2d98326e75c`.
  Those bytes are frozen and every correction is additive.
- `0010_m3_execution_admission_hardening.sql` requires an authenticated
  owner-matched personal profile and a prepared trusted Repository, binds the
  selected profile to the Worker, revalidates entry into `starting` and
  `working`, makes provider and Git runtime paths unique, preserves archive
  attribution, and closes the concurrent archive/run race with deferred
  consistency triggers. Its pre-merge SHA-384 is
  `75577885a942295b374e82fb96131e71d8f5b11c85f02908f95defee4711ca2da0ed0413995aab5c0c951dca63c2fa42`.
- Each retained or newly generated profile directory is created beneath the
  configured data root with descriptor-relative `mkdirat`/`openat`, no-follow
  directory opens, canonical containment, a restricted profile key, and Unix
  mode `0700`. A profile or root symlink is rejected without chmodding or
  creating content through its target.
- Before `0009`, startup may repair only the exact relative profile and mirror
  paths emitted by the known M0 development seed. It converts them to contained
  absolute paths and disables a Worker whose legacy dependencies are
  unavailable. Unknown paths, cross-Project ownership, duplicate host paths,
  or ambiguous resource identity fail closed for operator repair.

The early persistent smoke created one terminal `recovery test` run and one
already-canceled approval, without Messages, events, sessions, repositories,
or worktrees. Those two test-only rows were removed transactionally after their
exact identity and lack of dependents were verified. No accepted M0-M2 row or
filesystem object was removed. The eight retained terminal-run worktrees remain
unchanged.
