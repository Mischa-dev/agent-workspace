# M10 canonical Work Item application layer

## Scope

M10 removes the independent browser and MCP implementations of overlapping
Work Item commands. `apps/server/src/work_item_commands.rs` is the internal
application layer; `work_items.rs` and `mcp/writes.rs` remain HTTP and MCP
adapters.

The shared layer owns:

- title, description, single-line MCP text, and priority validation
- Project membership locking and centralized policy invocation
- Work Item `FOR UPDATE` projection and version/archive conflicts
- assignee eligibility and workflow status resolution/transition checks
- canonical top-level create and MCP subtask creation
- canonical field and status updates
- parent version advancement and reusable lock/projection helpers
- exactly-once activity and timeline insertion
- browser-session and MCP-credential audit attribution
- transactional outbox invalidation and addressed external-agent events
- append-only comment timeline/outbox/audit/external-event finalization

HTTP retains Origin/CSRF enforcement, `Idempotency-Key`, full Work Item
responses, Location headers, and HTTP conflict envelopes. MCP retains scoped
credential authorization, `clientRequestId`, stable `WriteResult` shapes,
tool schemas/descriptions, replay markers, and credential/channel audit
metadata. Structured browser comments retain mentions and Work Item reference
projections; MCP updates remain bounded plain text. These are intentional
transport semantics, not duplicated domain mutations.

## Compatibility

- Existing HTTP routes and camel-case JSON contracts are unchanged.
- Existing MCP tool names, descriptions, schemas, annotations, and result
  shapes are unchanged.
- No frontend behavior or API client was changed.
- No migration or database constraint changed.
- Existing activity kinds, audit actions, outbox payloads, external-event
  kinds/recipients, no-op behavior, and idempotency scopes are retained.

## Correctness evidence

The M4 HTTP, M6 MCP, and M9 external-agent PostgreSQL suites characterize
authorization, cross-Project non-disclosure, normalized state, optimistic
versions, replay and payload mismatch, archive conflicts, assignee membership,
activity/timeline attribution, audit channels, outbox invalidations, and
external recipient selection. M10 adds explicit browser-versus-MCP create and
update parity assertions in `m6_mcp_foundation.rs`: equivalent inputs produce
equal canonical row state and each surface adds exactly one activity, audit,
and outbox row per mutation.

## Exclusions

M10 does not add a task microservice, second database, synchronization system,
message broker, schema rewrite, dedicated task application, new public API,
public/shared SDK, role or workflow changes, UI redesign, or autonomous status
automation. A dedicated task UI or reusable external SDK requires its own
contract and authorization milestone.
