## Accepted boundary

M4 adds one canonical, optimistic-versioned Work Item with Project-owned
workflow definitions, stable readable keys, list and Kanban projections,
Actor-compatible assignment, ordered acceptance criteria, immutable structured
comments, typed activity, Thread and Repository links, structured Work Item
references, and an idempotent Work-with-Worker action. The action creates and
links a normal Thread before invoking the accepted M3 scheduler. It sends only
the immutable Work Item ID and key plus explicit user instructions to the
provider, uses deterministic Repository selection, and never changes Work Item
status as a side effect of Worker completion.

The Work Item workflow remains read-only in M4. GitHub delivery, pull requests,
checks, reviews, and Work Item automation remain M5 responsibilities.
