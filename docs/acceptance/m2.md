## Acceptance boundary

The candidate M2 implementation evolves the accepted M0/M1 schema and
authenticated application rather than introducing parallel Conversation
models. It adds production-shaped Channels, one-level Threads, immutable
Actor-authored Messages, structured Actor mentions, independent read cursors,
transactional outbox publication, one session WebSocket, compact Project
navigation, and archived-history access.

This document is not yet an acceptance declaration. The candidate has passed
the working-tree checks recorded below, but the exact green commit has not yet
completed GitHub CI, immutable Red Hat deployment, service-restart proof, or
browser-driven two-Actor acceptance. Those gates remain explicitly pending.

## Schema and migration evidence

- `0005_m2_conversations.sql` evolves the existing `conversations`,
  `messages`, `agent_run_events`, and `conversation_entries` tables and adds
  origin linkage, archive attribution/versioning, immutable Message guards,
  read states, idempotency records, and the transactional outbox.
- PostgreSQL constraints and triggers reject Channel repository bindings,
  nested Threads, cross-Project parents, wrong-Channel origin Messages,
  cross-Conversation timeline entries, Message mutation, invalid mentions,
  backwards or future read cursors, and archive while a non-terminal run is
  owned by the Conversation.

  IDs and ordering.
- `conversation_entries.sequence` remains the sole durable per-Conversation
  ordering cursor; a concurrent PostgreSQL test allocated sequences `1..=40`
  without a gap or duplicate.

## Message, Conversation, and read-state evidence

- The version-one Message AST accepts only text and Actor-mention nodes,
  denies unknown fields, derives plain text on the server, and applies the
  recorded node, text, mention, UUID, handle, and control-character bounds.
- Message authorship is resolved from the authenticated session. A submitted
  `authorActorId` is rejected, and every semantic mention is revalidated as an
  active same-Project membership before commit.
- Authorized APIs cover Channel creation/listing, bounded mention search,
  Channel and Thread Message append, linked Thread creation, opaque keyset
  timeline pagination, mark-seen, compact sidebar projection, and versioned
  Channel/Thread archive.
- Append and create commands bind a bounded idempotency key to Actor, resource,
  action, and request hash. An exact retry returns the canonical result while a
  changed payload conflicts.
- Missing and unauthorized Conversations share the same `404 Not Found`
  response. Archived history is hidden from ordinary reads and remains
  available to authorized callers through the explicit archived view.
- The development seed is idempotent and now retains two human Actor fixtures
  with independent Conversation read cursors. The second browser credential is
  provisioned only through the development-only, loopback-only host command;
  no password is accepted through a command-line option.

## Realtime and outbox evidence

- Every durable M2 Conversation, Message, archive, and read-state change writes
  a bounded typed outbox row in the same PostgreSQL transaction.
- The supervised publisher claims committed rows in database cursor order with
  a short lease, publishes at least once, and marks publication without
  claiming browser receipt. Stable event IDs make duplicate delivery harmless.
- Malformed poison events receive a bounded redacted diagnostic and do not
  prevent later valid events from publishing. A committed unpublished row is
  recovered by a restarted publisher without database repair.
- The frontend opens one authenticated session WebSocket, validates bounded
  version-one envelopes, ignores duplicate and unknown-future durable events,
  coalesces Project-scoped invalidation, and refetches HTTP state after
  reconnect. PostgreSQL and HTTP remain authoritative.
- The existing bounded ephemeral provider-delta path remains available for the
  M0 hosted-run compatibility slice; it does not become durable state through
  the WebSocket.

## Frontend evidence

- Routed Channel and Thread workspaces render paginated durable timelines with
  semantic Actor mentions, stable optimistic Message retries, load-older,
  mark-seen after render, linked Thread creation, archive fallback, and
  content-read-only archived history. The viewing Actor's private seen cursor
  may still advance after durable history is rendered.
- Persisted content is rendered as React text and semantic mention elements;
  hostile markup is not inserted as HTML, malformed or future AST content
  receives a safe plain-text fallback, and unavailable Actors receive an
  explicit label.
- The composer retains its draft and idempotency key on retry, inserts Actor IDs
  through a keyboard-accessible picker, restores focus on dismissal, and keeps
  literal `@agent` input as text unless the Actor is selected semantically.
- The Project sidebar renders active Channels and the server-defined compact
  Thread projection with text labels in addition to color, exposes `Show more`
  and archived history, and preserves the accepted M1 rail/sidebar drawer and
  remembered-route behavior.

## Pending Red Hat and browser acceptance

The following evidence must be added before changing this document to
`Accepted` or authorizing M3:

1. Commit the candidate, push its pull request, and record one exact commit for
   which the required GitHub `rust` and `web` jobs are green.
2. Deploy that exact commit as a new immutable Red Hat release without changing
   existing applications, ports, Tailscale routes, system Node, global Codex,
   or unrelated Podman projects.
3. Run migrations through `0008`, run the idempotent seed twice, and verify that
   retained M0/M1 history and both human Actor fixtures remain consistent.
4. Through SSH-forwarded `127.0.0.1:3100`, sign in as Actor A, create a Channel,
   send a Message that semantically mentions Actor B and `@agent`, create an
   origin-linked Thread, and paginate its durable timeline.
5. Sign in through an isolated second browser session as Actor B, prove an
   independent unread cursor, render and mark the same entries seen, then prove
   Actor A's cursor is unchanged.
6. Disconnect or suppress realtime delivery, create durable state, reconnect,
   and prove that one session WebSocket plus HTTP refetch converges without a
   duplicate Message or consumed read cursor.
7. Restart `agent-workspace.service` with a committed outbox row unpublished,
   then prove supervised publication recovery and Project-scoped browser
   convergence without manual database repair.
8. Archive the linked Thread, verify ordinary navigation falls back to its
   parent Channel, and verify both authorized Actors can still reach the
   explicit content-read-only archived history while retaining normal private
   seen-cursor semantics.
9. Inspect bounded service logs, database payloads, browser responses, and
   process environments for credentials, tokens, unsafe control characters,
   raw provider payloads, and unbounded content.
10. Re-run all required checks against the accepted commit, update the source
    status to `M2 satisfied; M3 active`, and record the exact release, CI run,
    browser evidence, and post-restart integrity result here.
